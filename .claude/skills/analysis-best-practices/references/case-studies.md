# 分析力の成功事例・失敗事例

## 成功事例

### 1. ジョン・スノウとコレラの地図（1854年、ロンドン）
医師ジョン・スノウは、当時「空気感染」が定説だったコレラの原因を、患者の死亡場所を地図上に
プロットすることで特定した。ソーホー地区の死亡例がブロード・ストリートの給水ポンプ周辺に
集中していることを可視化し、さらに2つの水道会社（給水元の違う地域）の間で死亡率を比較する
「自然実験」を行い、供給元の水道会社によって死亡率が14倍も違うことを示した。
→ **教訓**: 地図・比較対照群という単純な道具でも、仮説（水が媒介）と対抗仮説（空気感染）を
区別できるデータの取り方をすれば、当時の医学の定説を覆せる。相関を主張するには比較対象が要る。

### 2. トヨタ生産方式の「なぜなぜ分析」
トヨタは設備故障や品質不良に対し、「なぜ」を5回程度繰り返して表面的な対処
（部品交換）ではなく構造的原因（フィルター未設置などの仕組みの欠陥）に到達するまで掘り下げる
文化を徹底した。
→ **教訓**: 症状への対処を「解決」と呼ばない。原因が仕組みに達するまで掘らないと同じ問題が
再発する。

### 3. Amazonの「Correction of Errors（COE）」プロセス
Amazonは障害・ミスが起きるたびに、影響を定量化し、「なぜなぜ分析」で根本原因を特定し、
根本原因に対する是正措置を義務付ける社内プロセス（COE）を運用している。多くの企業の
「ポストモーテム」が症状への対処で終わるのに対し、COEは根本原因への対策を必須にしている点が
特徴。
→ **教訓**: 原因究明のプロセスを個人の技量に頼らず、組織の標準手順として制度化すると、
再発防止が定着する。

### 4. マネーボール — オークランド・アスレチックスの采配（2002年〜）
球団GMのビリー・ビーンは、スカウトの経験則・直感（「あの選手は見た目が良い」）ではなく、
出塁率など従来軽視されていた統計指標を使って選手を評価し、低予算ながら好成績を残した。
→ **教訓**: 「なんとなく良さそう」という定性的直感より、正しい指標（何を測るべきか）を選んだ
データが勝る。ただし指標選び自体が分析の核心であり、既存の常識を疑う姿勢が要る。

### 5. Netflixのデータ駆動型カルチャー
Netflixは視聴データ（何を・どこまで・いつ見たか）を継続的に分析し、レコメンドやコンテンツ
投資判断に反映し続けた。対照的に、後述のBlockbusterは店舗型ビジネスの延命に固執し、
配信への移行を分析よりも既存事業の防衛で判断した。
→ **教訓**: 分析を一度きりのレポートで終わらせず、意思決定に継続的に組み込む仕組みを作った
側が生き残った。

## 失敗事例

### 1. スペースシャトル「チャレンジャー号」爆発事故（1986年）
打ち上げ前夜、O-リング（部品の密閉ゴム）が低温で弾性を失い、燃料漏れを起こす懸念を技術者が
訴えていたが、NASA管理層は打ち上げを承認した。事故調査でリチャード・ファインマンが、O-リング
片を氷水に浸すだけの単純な実験で低温下での弾性喪失を再現し、根本原因を明らかにした。
問題はさらに、過去のデータ分析にもあった。「O-リング損傷が発生した打ち上げ」だけをグラフ化し、
「損傷が発生しなかった低温での打ち上げ」を除外していたため、温度との相関が過小評価されていた。
→ **教訓**: (1) 現場の懸念を示すデータより組織の予定・体面を優先すると重大事故につながる。
(2) 「起きなかったケース」を除外したグラフは相関を見誤らせる。都合の良いデータだけを見ない。

### 2. ロングターム・キャピタル・マネジメント（LTCM）の破綻（1998年）
ノーベル経済学賞受賞者を含む陣容が、精緻な数理モデルに基づき高レバレッジで運用していたヘッジ
ファンドが、ロシアの債務不履行という「モデルが想定していなかった」市場変動で破綻寸前に陥り、
連邦準備銀行主導の救済に至った。
→ **教訓**: 過去データに基づくモデルは「モデルの前提が崩れる事態（テールリスク）」を過小評価
しがちである。高レバレッジは分析の誤差を破滅的な結果に増幅する。プレモータム（「前提が外れたら
どうなるか」）を欠いた分析は危険。

### 3. Zillow Offers（iBuying事業）の失敗（2021年）
不動産大手Zillowは、AIによる自動査定（Zestimate）を使って住宅を買い取り転売する事業
「Zillow Offers」を展開したが、住宅価格を3〜6ヶ月先まで予測するモデルの精度が急変する市場に
追いつかず、約7,000戸を相場より高く買い過ぎた。2021年11月に事業撤退、5億ドル超の損失、
従業員の25%削減に至った。
→ **教訓**: モデルの予測精度が実運用のスピード（正確性より成長優先の意思決定）に追いつかない
まま規模を拡大すると、誤差がそのまま損失に直結する。予測モデルには「外れたときの損失規模」への
配慮と、継続的な精度検証が要る。

### 4. Target（米小売大手）の妊娠予測アルゴリズム（2010年代前半）
統計担当アンドリュー・ポールは、無香料ローションなど約25品目の購買パターンから妊娠確率を
高精度で推定するモデルを構築し、時期に合わせたクーポンを送付した。技術的には優れた分析
だったが、10代の娘に妊娠関連のクーポンが届いたことで父親がTargetに抗議し、後に妊娠の事実が
発覚するという事件が起き、プライバシー上の大きな反発を招いた。
→ **教訓**: 分析の精度が高いことと、その分析結果をどう使うべきかは別の問題。「予測できる」と
「予測結果を通知してよい」の間には倫理的な検討（プレモータム的な二次影響の検討）が必要。

### 5. コダック（Kodak）— 自社のデータを活かせなかった失敗
コダックの技術者スティーブン・サッソンは1975年に世界初のデジタルカメラを開発したが、
フィルム販売という既存事業を守るため社内でお蔵入りにした。市場がデジタルへ移行する兆候は
社内にも存在していたが、組織的なバイアス（自社の主力事業を否定したくない）が分析結果よりも
優先され、2012年に破産法適用に至った。
→ **教訓**: 正しいデータ・予兆が社内にあっても、組織の利害が分析結果の採用を妨げることがある。
分析の質だけでなく、それを意思決定に反映させる仕組みが要る。
