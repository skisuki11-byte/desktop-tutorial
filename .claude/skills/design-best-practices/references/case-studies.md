# 成功事例・失敗事例と教訓

デザインの判断は「好み」ではなく「過去に何が機能し、何が失敗したか」に基づかせる。
ここに挙げる事例は広く知られたデザイン史上の代表例。判断に迷ったら該当する事例を引用して自分の選択を説明する。

## 成功事例

### Apple Human Interface Guidelines（一貫性の勝利）
iOS/macOS 全体で余白・タイポグラフィ（San Francisco フォント／Dynamic Type）・アイコンの視覚言語を
統一し、アプリをまたいでも学習コストがほぼゼロになった。
**教訓**: 色・角丸・余白・フォントサイズを「トークン化」して使い回すと、個々の画面の完成度以上に
プロダクト全体の信頼感が上がる。→ このリポジトリでも複数アプリ間でトークンを揃える価値がある。

### Google Material Design（階層をモーションと影で表現）
「紙のメタファー」で、影（elevation）とモーションによって何が浮いていて何が押せるかを直感的に示した。
リップルエフェクトはタップへの即時フィードバックとして体感速度を上げた。
**教訓**: 操作した直後に何かが起きたと分かるフィードバックは、実際の処理速度以上に「速い」と感じさせる。

### Stripe（配色とタイポグラフィの禁欲主義）
決済という信頼が命の製品で、アクセントカラーをほぼ1色に絞り、大きな余白と高品質なタイポグラフィで
「情報量を減らして見せる」ことに徹した。開発者向けドキュメントの読みやすさも業界標準になった。
**教訓**: 色数・装飾を増やすことは「デザインした感」を出しやすいが、実際は減らす方が信頼感と可読性が上がる。

### Airbnb Design Language System（イラストと色でブランドの温度感を統一）
Web/iOS/Androidの3チームがバラバラに実装していたUIを、共通のデザイン言語（コンポーネント・色・
イラストスタイル）に統一。開発速度も上がり、見知らぬ人の家に泊まるサービスに必要な「安心感」を
一貫したビジュアルで補強した。
**教訓**: 見た目の一貫性は「美しさ」だけでなく「信頼」という機能的な価値を持つ。

### Duolingo型ゲーミフィケーション（継続を後押しするフィードバック）
連続学習日数・プログレスリング・キャラクターによる褒め言葉など、達成感を可視化する仕組みで
継続率を大きく改善した。**このリポジトリの英単語アプリ（README記載の「連続学習日数」「習得率リング」）は
まさにこの成功パターンを内包している**。他の記録系アプリ（家計簿・配当金）にも応用できる。
**教訓**: 記録・学習系アプリは「入力させて終わり」ではなく、続けたくなる小さなご褒美（進捗の可視化）が効く。

### 家計簿・資産管理アプリ（Mint等）の数値の見せ方
合計金額を最大フォントで最上部に置き、内訳をグラフ・カテゴリ色で補助する構成が定番化している。
数字は必ず桁位置が揃うフォント（等幅数字）で表示し、パッと見て桁を読み間違えないようにしている。
**教訓**: cashbook / dividend のような数値主体アプリでは「一番知りたい数字」を即座に見せる設計が最優先。

## 失敗事例

### Windows 8 スタート画面（2012）
デスクトップPC・マウス操作のユーザーにも、タッチ前提のフルスクリーンタイルUIとスタートボタン廃止を
一律に強制した。既存ユーザーの操作の型を無視した結果、大きな反発を招き、Windows 8.1・10で
スタートボタンを復活させることになった。
**教訓**: 「新しい」デザインパラダイムを、実際の利用環境・利用者を無視して一律に押し付けない。
このリポジトリのアプリはスマホ利用が主だが、それぞれ用途（記録・閲覧・クイズ）が違うため、
UIパターンを機械的に統一しすぎず、各アプリの使われ方に合わせる。

### Digg v4（2010）
大規模リニューアルで、ユーザーが日常的に使っていたコア機能（投稿・投票の使い勝手）を壊す形の
アルゴリズム／UI変更を行い、既存ユーザーが数週間で競合（Reddit）へ大量離脱した。
**教訓**: 見た目を刷新するリニューアルでも、ユーザーが依存している核となる操作導線を壊してはいけない
（原則8「機能を壊さない改悪をしない」に直結）。

### Snapchat 2017リニューアル
友人のストーリーとメディア企業のコンテンツを同じ画面に混在させる情報設計変更を行い、
中心ユーザー層が混乱。100万人超の反対署名が集まるほどの反発となり、翌年一部を差し戻した。
**教訓**: 情報設計（何をどこに置くか）の変更は見た目の変更よりも影響が大きい。よく使われている
導線を動かす前に「本当にこれで迷わないか」を検証する。

### GAP ロゴ刷新（2010）
ブランドの象徴であるロゴを、説明や移行期間なしに刷新して公開し、わずか6日で猛反発により旧ロゴに戻した。
**教訓**: 見た目を変える理由・背景を説明せずに変更すると、変更自体の良し悪しに関わらず拒否反応を招く。

### Juicero
高価で高度な工業デザインのジューサー本体を作ったが、実際には専用パックを手で絞るだけで同じ効果が
得られることが発覚し、嘲笑の対象になった。
**教訓**: 「デザイン（見た目・作り込み）」に凝ることは、それが解決する本質的な価値を伴わなければ
意味がない。装飾より先に「そもそも何を解決したいか」を明確にする。

### MySpaceの自由すぎるカスタマイズ
ユーザーに無制限のカスタムCSSを許可した結果、視認性の低い・崩壊したプロフィールページが乱立し、
プラットフォーム全体の一貫性と使いやすさが損なわれた。後発のFacebookは統一されたシンプルな
テンプレートで使いやすさを担保し、ユーザーを奪っていった。
**教訓**: 自由度の高さは魅力に見えるが、一貫性・可読性とのトレードオフになる。個人開発アプリでも
「毎回好きな配色を新規に考える」のではなく、共通トークンの範囲内でカスタムする方が全体の質が上がる。
