# このリポジトリ向け実践チェックリスト

対象: cashbook（家計簿）, dividend（配当金管理）, yosou（予想）, solar（太陽光）, sekaishi（世界史）,
youtube, および今後追加される新規アプリ。すべて依存ライブラリなし・ビルド不要の静的 HTML/CSS/JS、
PWA（manifest.webmanifest / sw.js）構成でスマホ利用が主。

新規作成・改修のどちらでも、以下を上から順に確認する。

## 共通（全アプリ）

- [ ] ダークモード (`prefers-color-scheme: dark`) に対応している（既存アプリの慣習に合わせる）
- [ ] 配色は CSS 変数（トークン）化されており、アクセントカラーは実質1色に絞られている
- [ ] 本文コントラスト比 4.5:1 以上を満たしている（特にダークモード側を目視確認）
- [ ] フォントは日本語フォントスタックを使い、行間 1.6 以上
- [ ] 余白は 4px/8px ベースのスケールで統一されている（バラバラな px 値を使っていない）
- [ ] タップ対象は 44×44px 以上（ボタン・チェックボックス・リスト項目など）
- [ ] 色だけで意味を伝えていない（増減・正誤などは記号やアイコンも併用）
- [ ] 保存・削除・記録などの操作に短いフィードバック（色変化・チェックマーク等）がある
- [ ] フォーカスリングを消していない、またはキーボード操作の代替スタイルがある
- [ ] オフラインで問題なく動く（sw.js のキャッシュ対象に新規ファイルを追加したか確認）

## 数値主体のアプリ（cashbook / dividend / yosou / solar）

- [ ] 最も知りたい数字（合計金額・年間配当・予想結果など）が画面最上部・最大サイズで表示されている
- [ ] 金額・日付など桁を揃えたい数字に `font-variant-numeric: tabular-nums` を指定している
- [ ] 増加/減少・収入/支出は色（緑/赤）＋記号（+/−）の両方で示している
- [ ] 一覧・表はカテゴリごとの視認性（色分け・区切り線）が過剰でない（原則5：情報を減らして見せる）

## 記録・継続系アプリ（学習・記録の習慣化を狙うもの）

- [ ] 連続記録日数・達成率など、続けたくなる小さなフィードバックがあるか検討した
  （英単語アプリの「連続学習日数」「習得率リング」のパターンを流用できないか確認）

## 新規アプリを作るとき

- [ ] 既存アプリ（cashbook, dividend, solar, youtube 等）の `css/style.css` を確認し、
      配色・角丸・余白のトークンを流用できないか先に検討した（アプリ間の一貫性）
- [ ] 見た目を凝る前に、そのアプリが解決したい本質的な価値（何を記録・計算・表示したいか）を
      1文で説明できる状態にした（Juicero の教訓：機能なきデザインをしない）

## 既存アプリを改修するとき

- [ ] 改修前に「そのアプリで一番よく使われている操作」を特定した
- [ ] その操作の手数（タップ数・迷いやすさ）が改修後に増えていないか確認した
      （Digg v4 / Snapchat 2017 の教訓：見た目の刷新でコア導線を壊さない）
- [ ] ロゴ・アイコン・配色など「見慣れたもの」を変える場合、変える理由を説明できる状態にした
      （GAPロゴの教訓：唐突な変更は理由の説明なしに反発を招く）
