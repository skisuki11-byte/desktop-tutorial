# 申し込みフォーム＋役員集計アプリの作り方（春高チケットで得たノウハウ）

実例：`ticket/`（保護者用 `ticket/index.html`、役員用 `ticket/admin.html`、集計先 `ticket/gas/Code.gs`）。
新しく作るときは、このフォルダをひな形としてコピーし、`js/config.js` と `gas/Code.gs` の項目・値段・日付を差し替えるのが最短。

## 1. 構成の決め方（最初に確認すること）

- **入力する人がアカウントを持っているか**で決める。保護者・部員・OB はたいてい claude.ai アカウントを持たない。
  Artifact の db は組織外の人が書き込めないので不向き。→ **GitHub Pages の静的ページ＋Google Apps Script（GAS）＋スプレッドシート**。
- 集計を見る人（役員）は数名で、合言葉1つを共有する方式にする（Google アカウント不要）。
- **入力画面に役員ページへのリンクを置かない**。役員ページは別URL（`admin.html`）を役員だけで共有。
- `config.js` の `endpoint` が空のあいだは「デモ表示」（localStorage・見本データ・合言葉 `demo`）。本番前の確認やスクショに使える。

## 2. 入力画面（人間中心設計）

- 流れは **入力 →［確認する］→ 確認（内容を大きく表示＋注意事項）→［申し込む］→ 完了（受付番号）**。
  確認・完了には **［修正する］** を並べ、完了には **［閉じる］**（`window.close()` は効かないことが多いので「ありがとうございました」画面へ）。
- **スマホ1画面に収める**（390×664＝Safari/LINEの見える範囲で［確認する］までスクロールなし）。
  背の低い画面（`max-height` メディアクエリ）では段階表示や英字の小見出しを隠して詰める。Playwright で 390×664・375×560・360×640 を測る。
- 欄は最小限（Expedia の「欄を1つ減らして増益」）。任意の欄は「任意」と明示。名前とコートネームは横並びにして高さを節約。
- 枚数は **日付×区分の表＋−／＋ボタン**（44px以上）。合計枚数と金額はその場で表示（Baymard：想定外の費用は離脱理由1位）。
- 注意事項は「いちばん間違えやすい2つ」を入力欄の上に、全文は申し込む直前の確認画面に（GOV.UK の宣言パターン）。
- 同じ端末で開き直すと「申し込み済みです」と修正・取り消しの入り口だけ（入力欄は出さない＝二重申し込み防止）。
  端末には受付番号と**合鍵（token）**だけを保存。サーバーで消された申し込みは端末の記録からも外す。
- 通信が切れても二重登録にならないよう **requestId（冪等キー）** を送る。

## 3. 役員の集計画面

- 役員の仕事の順に並べる：**01 発注する数（日付×区分の内訳表・金額）→ 02 集金 → 03 受け渡し**。
- 集金・受け渡しのカードを押すと「まだの家庭」だけに絞る。**絞り込み中は帯で「◯◯の家庭だけを表示中」＋［× すべてに戻す］**を必ず出す（迷子防止）。押したカードは「表示中」、もう一度押すと戻る。
- 似た名前のボタンが上下に並ばないようにする（例：しぼりこみ「すべて」と日付「全日」）。
- 集金・受け渡しのチェックに **つけた役員名と時刻** を残す（二重集金防止）。役員名は合言葉の画面で必須入力。
- **取り消し・記録を外す** ときは「誰の・何枚の」を見せた確認ダイアログ（初期選択は［やめる］）＋［元に戻す］トースト。よく押す「済みにする」には確認を出さない。
- 状態は色だけでなく文字（まだ／済み）と枠（点線／実線）でも区別。1分ごとに自動更新。LINE用の集計コピー、CSV（BOM付き・数式無害化）。

## 4. GAS（集計先）

- コンテナバインド（スプレッドシートの 拡張機能→Apps Script）。先頭に `/** @OnlyCurrentDoc */` を置けば appsscript.json を貼り替えなくても権限が「このシートだけ」になる。
- 公開は「ウェブアプリ・自分として実行・全員」。コードを直したら **デプロイを管理 → 新バージョン**（URLは変わらない）。新しいデプロイを作るとURLが変わるので注意。
- 画面からは `Content-Type: text/plain` で POST（CORS の事前確認を避ける）。
- 合言葉はスクリプトのプロパティ `ADMIN_PASS`。**リポジトリには絶対に書かない**（公開リポジトリのため）。
  比較は表記ゆれを吸収（NFKC・ひらがな→カタカナ・小文字化・空白除去）。20回失敗で10分ロック。
- **スマホのパスワード欄は日本語を入力できない**ので、合言葉欄は通常の text 入力にする。
- シートへの書き込みは `= + - @` 始まりに `'` を付けて数式化を防ぐ（読み戻して書き戻すときも毎回）。
- LockService の tryLock が取れないときは例外にせず `busy` を返す。ボット対策に見えない欄（honeypot）。
- 画面とGASで日付・区分・値段を二重に持つので、**食い違いをテストで検出**（`ticket/tests/gas.test.js`）。
  GAS は vm＋配列のシート模型でテストできる。

## 5. セキュリティ・軽さ

- 画面に出す値はすべて `textContent`（innerHTML は固定の SVG のみ）。
- `<meta http-equiv="Content-Security-Policy">`：script-src 'self'、style-src 'self' fonts.googleapis.com、font-src fonts.gstatic.com、
  connect-src **script.google.com と script.googleusercontent.com**（GAS はリダイレクトするので両方）、base-uri/form-action/object-src 'none'。
- 見出しの太字和文フォント（Dela Gothic One）は `&text=` で使う文字だけ読み込む（文字を増やしたら text も更新）。
- 行事が終わったらシートを削除するよう案内（生徒名が残る）。

## 6. デザイン（このユーザーの好み）

- **白基調**（ダークモードでも白のまま）。紺＝文字、ボールの黄色＝押すもの・選択中・強調線だけ。
- 見出しは全国大会らしく：極太の「春高」＋ボールのマーク＋スピード帯＋ネット目。**「◯◯部 専用」**の札で対象を明示。
  保護者用は白地、役員用は紺地＋「役員専用」（取りちがえ防止）。
- 合計は得点板風（紺の帯・黄色の数字・白い金額札）、確認・完了はチケットの券面（ミシン目・受付番号）。
- 大きなデザイン変更は先に Claude Design（Artifact の Design 型）で案を作り、OKが出たら本番へ反映。

## 7. 作業の進め方（このリポジトリ・このユーザー）

- ユーザーは途中で要望を足していく。都度、小さな PR にして **「マージまでして」と言われたらマージまで**行う。
- PR の見張り（subscribe）は不要と言われている。自動で始まったら unsubscribe する。
- マージ済みのブランチへ force push は拒否される → **新しいブランチ名**で出す。
- この環境から github.io・script.google.com には接続できない。本番の確認はユーザーに依頼し、そのことを毎回はっきり伝える。
- 1つのコマンドに複雑な処理を詰めると安全チェックで止まることがある → サーバー起動・スクリプト作成・実行を分ける。
