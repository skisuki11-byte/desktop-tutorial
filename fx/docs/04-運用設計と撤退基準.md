# 04. 運用設計と撤退基準

検証を通った束を、実際に動かすための設計。
Phase 2（デモ）以降で必要になる。Phase 1 では読むだけでよい。

## 1. 業者・APIの前提

> **2026年8月時点の調査結果。変わりうるので着手前に必ず再確認すること。**

| 業者 | API | 条件 |
|---|---|---|
| **OANDA証券** | v20 API あり | **デモ口座のみでは利用不可**。本番口座＋会員ステータスGold＋プロコース＋NYサーバー残高25万円以上＋API契約書への同意 |
| **IG証券（日本法人）** | **なし** | Web／モバイルのみ |

OANDA の Gold 維持には月50万ドル以上の取引が必要。
ただし **新規開設の翌月末まではGold扱いになる特典** がある。

> つまり「デモで気軽にAPI自動売買」は日本ではできない。
> だからこそ、口座を作る前に検証を済ませる順番が合理的。

### 口座開設のタイミング

[01](01-目標とリスク設計.md) §6 で実効レバレッジ上限を10倍と決めた。
国内FXの上限は25倍なので制度上は問題ないが、
**Gold特典の期限（開設翌月末）とデモ3ヶ月が噛み合わない。**

対応：束が [03](03-検証プロトコル.md) §5 を通過してから口座を開設し、
特典期間中に **API疎通確認と発注ロジックの検証** を済ませる。
戦略の良し悪しの判断はすでに終わっている前提。

## 2. リスク管理の3層

[02](02-アーキテクチャ.md) §8 の `risk.yaml` を、なぜその値かとあわせて整理する。

### 層1：ボラターゲティング（常時作動）

実現ボラを20営業日EWMAで測り、目標ボラに合わせて建玉をスケールする。

```
scale = target_vol / realized_vol      （上限は max_leverage でクリップ）
```

**クリップが必須である理由** ―
低ボラ局面では `realized_vol` が小さくなり、scale が青天井に上がる。
そこでボラが平常に戻ると、想定の数倍の建玉で被弾する。
低ボラ期に膨らんだレバレッジがボラ回帰で吹き飛ぶのは、
自動売買の典型的な壊れ方。

### 層2：DDガバナー（段階的）

| ドローダウン | レバレッジ倍率 | 位置づけ |
|---|---|---|
| 10% | ×0.70 | よくある。減速するだけ |
| 15% | ×0.50 | やや深い |
| 20% | ×0.30 | 想定の中央値付近（S=1.5・ボラ30%でDD中央19.0%） |
| **30%** | **×0.00** | **全停止・再検証**（90%点29.8%を超えた＝想定外） |

閾値の根拠は 01 §3 のDD分布。
**DD20%は「よくあること」、DD30%は「めったにないこと」。**
20%で全停止すると正常な変動で運用が終わる。
30%まで何もしないと異常を見逃す。だから段階的に落とす。

### 層3：キルスイッチ（即時・全決済）

| 条件 | 閾値 | 理由 |
|---|---|---|
| 日次損失 | 資金の5% | ボラ30%運用の日次標準偏差は約1.9%。5%は2.6σ相当＝異常 |
| 連続損失 | 10回 | 戦略の前提が壊れた可能性 |
| スプレッド異常 | 5.0 pips超 | 早朝・指標時。コストがエッジを上回る |
| データ遅延 | 120秒 | 古い価格で発注するのが最も危険 |

`HALTED` からの復帰は **必ず手動**。
自動復帰させると原因不明のズレを抱えたまま発注を再開する。

## 3. インフラ

| 項目 | 方針 | 理由 |
|---|---|---|
| 実行環境 | **VPS**（東京リージョン） | 自宅PCの停電・回線断でポジション放置は現実に起きる |
| 監視 | 死活監視＋建玉の定期通知 | プロセスが落ちたこと自体に気づけないのが最悪 |
| 通知 | 発注・キルスイッチ・DDガバナー発動 | 平常時は静か、異常時だけ鳴るように |
| バックアップ | journal（JSONL）を日次で外部保存 | 「なぜその発注をしたか」を失うと事後検証ができない |
| 時刻 | NTP同期必須 | 足の境界判定がずれると戦略が別物になる |

VPSが落ちている間にポジションを持ったままになるリスクは、
**業者側のロスカット設定** でしか守れない。
建玉を持つ戦略には必ず逆指値を置く（システム側の判断に依存しない防御）。

## 4. 税務

| 項目 | 国内店頭FX | 海外業者 |
|---|---|---|
| 課税方式 | **申告分離 20.315%** | 総合課税（累進、最大約55%） |
| 損失繰越 | 3年 | 不可 |
| 損益通算 | 先物・オプション等と可能 | 不可 |

[01](01-目標とリスク設計.md) §4 のとおり、税引後40%を目指すなら税引前50.2%が必要。
海外業者を使うと総合課税で必要リターンがさらに跳ね上がる。

> **国内業者・申告分離を前提とする。** 目標は税引前で管理し、
> 月次レポートに税引後を併記する。

年間取引報告は業者から出るが、**journal のログと突合して検算する。**

## 5. 段階的な増額

一度に資金を入れない。各段階で「次に進んでよいか」を確認する。

| 段階 | 資金 | 期間 | 次へ進む条件 |
|---|---|---|---|
| **デモ** | 0円 | 3ヶ月 | 実測シャープが検証値の60%以上 |
| **最小ロット** | 実弾・最小単位 | 3ヶ月 | 実測スリッページが想定内（後述） |
| **1/4** | 目標資金の25% | 3ヶ月 | DDガバナー未発動 |
| **1/2** | 50% | 3ヶ月 | 同上 |
| **満額** | 100% | ― | ― |

合計で **1年以上かける**。急ぐ理由がない。

### スリッページの検証方法

最小ロット期間の主目的は「儲けること」ではなく、
**バックテストの前提が現実と合っているかの計測**。

journal に記録した「発注時の想定価格」と「約定価格」の差を集計し、
[02](02-アーキテクチャ.md) §5.2 の `SpreadModel` 前提と比較する。

想定より悪ければ、その値でバックテストをやり直す。
**そこでエッジが消えるなら、そこで終わり。** 資金を増やしてはいけない。

## 6. 撤退基準

事前に決めておかないと、負けている最中には決められない。

### 即時停止（自動）

- キルスイッチのいずれかが作動 → 全決済・`HALTED`
- DD 30%到達 → 全停止・再検証

### 運用停止して再検証（手動判断）

| 条件 | 根拠 |
|---|---|
| 実測シャープが検証値の50%を **3ヶ月連続** で下回る | 単月なら分散の範囲。3ヶ月continuousは前提の崩壊を示唆 |
| 想定スリッページを **2倍以上** 超過 | コスト前提が誤り。バックテストごとやり直し |
| 束の平均相関が **0.5を超えた** | 分散が効かなくなっている。合成シャープが崩れる（01 §5） |

### 撤退（システムを畳む）

| 条件 | 根拠 |
|---|---|
| **3年累積でマイナス** | 01 §7 のとおり、S=1.5なら3年マイナスの確率は1.0%。起きたなら前提が間違っている |
| 再検証を2回行ってもシャープ1.0を回復しない | エッジが消えた（レジーム変化・他者の裁定） |

### 撤退基準にしないもの

| してはいけない判断 | 理由 |
|---|---|
| **単年で40%に届かなかったから止める** | S=1.5・ボラ30%でも達成確率は59%。4割の確率で普通に未達（01 §7） |
| **DD20%が出たから止める** | 想定の中央値付近（DD中央19.0%）。ガバナーが減速するのが正しい対応 |
| **数ヶ月マイナスだから戦略を入れ替える** | 最も高くつく間違い。負けた戦略を切り、勝った戦略を足すと、高値掴みを繰り返す |

**最後の行が実務上いちばん重要。**
「調子の悪い戦略を外す」判断は、事前に決めた基準（実測S 50%割れ×3ヶ月）だけで行う。
気分で入れ替えると、検証で積み上げた統計的な根拠がすべて無効になる。

## 7. 月次レビューでやること

| 項目 | 見るもの |
|---|---|
| 実測 vs 検証 | シャープ・PF・取引回数・平均保有時間のズレ |
| コスト | 実スリッページ vs 想定。乖離が広がっていないか |
| 相関 | 戦略間の直近3ヶ月相関。0.5に近づいていないか |
| レバレッジ | 実効レバが上限10倍に張り付いていないか（低ボラ局面の兆候） |
| 稼働率 | 25%を割っていないか |
| 税引後 | 税引前リターンと併記 |

レビューで **戦略を触らない**。
触ってよいのは `target_vol` と、事前基準に該当した戦略の除外だけ。
新しい戦略の追加は [03](03-検証プロトコル.md) の手続きを最初から通す。
