# 06. Phase 1 実行記録 ― 検証基盤の構築と検算

[03-検証プロトコル](03-検証プロトコル.md) §9 の手順1〜2に相当。
**「戦略にエッジがあるか」を調べる前に、「検証基盤が信用できるか」を確かめた記録。**

## 結論

✅ **検証基盤は正しく動いている。** エッジゼロのデータで正しく負け、
損失の内訳がほぼ全額売買コストになることを確認した。

❌ **実データはまだ取得できていない。** このコンテナのネットワークポリシーが
Trusted のため、HistData を含むFXデータ配信元がすべて遮断されている（§4）。

## 1. 実装したもの

| ファイル | 役割 |
|---|---|
| `fx/fx1.py` | バックテスト本体。戦略＝ポジション比率を返す純関数 |
| `fx/tools/spread_model.py` | 時間帯別スプレッドモデル（合成・実データで共用） |
| `fx/tools/make_synthetic.py` | エッジゼロのダミーデータ生成 |
| `fx/tools/sanity_check.py` | **検証基盤の自動テスト** |
| `fx/tools/import_histdata.py` | HistData M1 → M5 parquet 変換 |

### 設計書からの変更点

**損益を「価格差」ではなく「リターン」で測るようにした。**
Notion収録版は円建ての絶対損益（円/1万通貨）だったが、
[01](01-目標とリスク設計.md) のシャープ・ボラ・DDの議論と接続するには
建玉に対する率で測る必要がある。

**スプレッドの計上を半スプレッド×|Δpos| に修正した。**
Notion収録版は `|Δpos| × 全スプレッド` で、往復すると2スプレッド分を払う計算だった。
正しくは 0→+1 で ask で買い（mid比 +半スプレッド）、+1→0 で bid で売り（同）で、
**往復ちょうど1スプレッド**。保守的すぎる見積もりも判断を誤らせるので、実勢に合わせた。

**シャープに標準誤差を併記するようにした。**
[05 検証4](05-検証結果.md) の結論を実装に反映。点推定だけを出すと、
それを確定値として読んでしまう。

## 2. ランダムウォーク検算の結果

10年分（751,104本、2016-01-04〜2025-12-31）のエッジゼロデータで実行。

| 戦略 | 総リターン | グロス | 理論分布からの乖離 | コスト | シャープ | 判定 |
|---|---|---|---|---|---|---|
| breakout | **-11.09%** | +14.73% | 0.4σ | -20.62% | -0.05 | ○ |
| nakane | **-21.17%** | -2.39% | 0.4σ | -21.23% | -1.33 | ○ |

**両方とも負けた。これが正しい挙動。**
さらにグロスリターンがほぼゼロ（理論分布から0.4σ以内）で、
損失がほぼ全額コストで説明できている。損益計算そのものが正しい証拠。

## 3. 未来参照バグの再現 ― なぜ shift が絶対なのか

同じ戦略・同じデータ・同じコストで、`shift(1)` を外しただけの結果：

| 条件 | 総リターン | シャープ | 最大DD |
|---|---|---|---|
| 正しく1本ずらす | **-11.09%** | -0.05 | 37.60% |
| ずらさない（未来参照） | **+5,023.88%** | **3.99** | 5.32% |

**エッジがゼロのデータで、シャープ3.99・リターン+5,000%。**

### ここが重要 ― 統計ではこのバグを検出できない

この+5,023%の結果は、[03 §4.1](03-検証プロトコル.md) で導入した
**シャープの信頼区間下限も3.06** で、DSR足切りも余裕で超えて「合格」と出る。

**統計的な足切りは、選択バイアスには効くが、実装バグには一切効かない。**
だから [02 §6](02-アーキテクチャ.md) の「死守すべき2点」は
構造として守るしかない。検算はその構造が壊れていないことの確認。

## 4. 自動テストにした

手で確認する代わりに `fx/tools/sanity_check.py` にした。
戦略を追加したり `backtest()` を触ったら、まずこれを通す。

```
python fx/tools/sanity_check.py     # 合格なら exit 0
```

確かめること：

1. エッジゼロのデータで、すべての戦略が負ける
2. グロスリターンが理論分布の3σ以内（損益計算そのものの検算）
3. わざと shift を外すと勝つ（**テスト自体に検出力があることの確認**）

### テストを書いて分かった2つのこと

**① 固定の許容誤差は誤りだった**

最初「グロスは±2%以内」と書いたが、これは間違い。
エッジゼロでもグロスは乱数なので散らばり、その標準偏差は `σ×√(稼働率×年数)`。
常時建玉の breakout では34%にもなる。実測+14.73%は0.4σで正常だった。
**許容幅は稼働率と年数に比例させる必要がある。**

**② 仲値アノマリーでは shift のバグを検出できない**

仲値は時刻だけで建玉を決め、**価格を一切参照しない**。
そのため shift を外しても「未来の価格を知る」ことが原理的にできず、
窓が5分ずれるだけ（実測シャープ -0.38 で、むしろ悪化）。

| | 未来参照バグが起きるか | 検算に使えるか |
|---|---|---|
| nakane（時刻のみ） | **起きない**（安全） | **使えない**（検出力ゼロ） |
| breakout（価格依存） | 起きる | 使える |

安全な戦略ほど、検証基盤の検算には使えないという関係になる。
`fx1.py` の `PRICE_DEPENDENT` で区別し、価格依存の戦略にだけ検出力を要求している。

> Notionのメモは仲値を1本目に選んだ理由を「ルールが単純でパラメータがほぼ無く、
> 検証基盤の検算に向いている」としていたが、**shift の検算には向いていない**。
> 単純さの利点はそのままだが、検算には breakout が要る。

## 5. 実データの取得 ― ローカルでの手順

このコンテナのネットワークは **Trusted** ポリシーで、
以下がすべて遮断されている（CONNECT に 403）：

```
www.histdata.com        HTTP 000
histdata.com            HTTP 000
datafeed.dukascopy.com  HTTP 000
stooq.com               HTTP 000
```

クラウドで取得するには環境の Network access を `Custom` にして
`histdata.com` を許可リストに追加する必要がある。
ただし10年分のM1 CSVは展開後 数百MB〜1GB規模で、
**git に入れるべきではない**（`fx/.gitignore` で `*.csv` と `data/` を除外済み）。

### ローカルでの手順

1. https://www.histdata.com/download-free-forex-data/ から
   **USD/JPY・ASCII M1・2016〜2025** を年ごとにダウンロード
2. 展開した `.csv` を `fx/data/raw/` に置く
3. 変換：
   ```bash
   pip install -r fx/requirements.txt
   python fx/tools/import_histdata.py --src fx/data/raw --out fx/data/USD_JPY_M5.parquet
   ```
4. **必ず先に検証基盤を確認**：
   ```bash
   python fx/tools/sanity_check.py
   ```
5. 仲値アノマリーを検証：
   ```bash
   python fx/fx1.py fx/data/USD_JPY_M5.parquet --strategy nakane --trials 1
   ```

`--trials` には**それまでに試した累計本数**を渡す。
DSR足切り（[03 §3](03-検証プロトコル.md)）の計算に使うので、正直に数える。
