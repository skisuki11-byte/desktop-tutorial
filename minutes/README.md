# 議事録アプリ

スマホ・PCで録音すると、**画面に要点がリアルタイムで出続け**、会議が終わったら**きれいな議事録にして Notion に保存**するWebアプリです。
発言者は「話者A・B…」で自動判別され、**あとから名前を付けられます**。PCではブラウザで開いた **Teams 会議の音声もそのまま録れます**（Teams 連携ではなく、PC上で音を拾う方式）。

```
スマホ/PCブラウザ ──音声──▶ Deepgram（文字起こし＋話者分離） ─┐
        ▲                                                      ├▶ 画面に文字と要点
        └── サーバー(server.js) ── 要点更新・議事録 ──▶ Claude ─┘
                            └──▶ Notion（議事録ページ）
```

## 使い方（ローカル）

```bash
cd minutes
cp .env.example .env      # キーを記入（下記）
node server.js            # Node 18 以上。npm install は不要
# → http://127.0.0.1:8787
```

キーが無くても **「デモで試す」** で画面の動きと議事録の完成形を確認できます。

| 機能 | 必要なもの |
|---|---|
| 文字起こし・話者分離 | `DEEPGRAM_API_KEY`（[Deepgram](https://console.deepgram.com/)、権限は Member 以上） |
| 要点・議事録 | `ANTHROPIC_API_KEY`（[Anthropic Console](https://console.anthropic.com/)） |
| Notion 保存 | `NOTION_TOKEN` と `NOTION_PARENT`（下記） |

### Notion の準備（1回だけ）
1. <https://www.notion.so/profile/integrations> で「内部インテグレーション」を作成し、トークンを `NOTION_TOKEN` に。
2. 保存先にしたい**データベースまたはページ**を開き、右上「…」→「接続」→ 作ったインテグレーションを追加。
3. そのページの URL をそのまま `NOTION_PARENT` に貼る。データベースなら「日付」列（1つだけの場合）に会議日も入ります。

## Teams 会議を録る（PC）
1. 録音を開始 →「**マイク ＋ PCの音声**」を選択。
2. 共有ダイアログで、Teams を **ブラウザで開いている** なら「タブ」からそのタブ、**アプリ**なら「画面全体」（Windows）を選び、**「音声を共有」にチェック**。
3. 自分の声（マイク）と相手の声（PC音声）が1本にミックスされ、話者が自動で分かれます。ヘッドホンでも相手の声を拾えます。
- Mac は「タブ」の音声のみ共有可能です（Teams アプリの音は取れません。ブラウザ版 Teams を推奨）。
- 会議相手の画面にはボットは参加しません。ただし **参加者への告知は必須**です（開始時に確認チェックがあります）。

## スマホで使う
マイク利用には **HTTPS が必須**（`localhost` は例外）です。スマホから使うには、次のいずれかでサーバーを HTTPS 公開してください。
- 手軽: [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) / ngrok で `localhost:8787` を公開
- 常設: Render / Fly.io / Railway 等に `minutes/` をデプロイ（`HOST=0.0.0.0`）

> ⚠ **公開するときは必ず `ACCESS_TOKEN`（合言葉）を設定**してください。未設定だと URL を知った第三者があなたのAPIキーの課金を使えてしまいます。

録音中は画面が消えないよう Wake Lock を使いますが、**ブラウザを閉じる・別アプリに切り替える・端末をロックすると録音が止まる**ことがあります（特に iPhone）。会議中は画面を開いたままにしてください。

## 主な機能
- **常時表示の要点**: 「いまの議題／要点／決定／TODO／未解決」を約20秒ごとに更新。新しく増えた項目は数秒ハイライト。スマホは画面上部に固定、PCは左右2カラム。
- **話者A・B…→ 後から名前**: 名前を付けると、文字起こし・要点・議事録・Notion 全てに反映（議事録の作り直し不要）。誤判別は**発言ごとに話者を付け替え**、同一人物が分裂した場合は**統合**できます。
- **重要マーク**: 会議中にワンタップで印を付けると、議事録で優先的に扱われます。
- **高精度で再解析**: 終了後、録音全体から話者分離をやり直せます（ライブ結果は暫定のため）。
- **保存は手動**: 議事録は自動作成、**Notion への保存は自分で押したときだけ**。
- **クラッシュ復旧**: 音声は5秒ごとにブラウザ内へ保存。タブが落ちても直前までの録音から再解析できます。
- 全データ（会議・音声）は**この端末のブラウザ内**に保存。サーバーはAPI中継のみで何も保存しません。

## 設計の根拠（成功事例・失敗事例から）
| 事例 | 教訓 | 本アプリの判断 |
|---|---|---|
| **Otter.ai**（リアルタイム文字起こし＋話者ラベルを後から命名）| 「常に見える要約」と「話者を後で命名」が支持された型 | 同じ体験を採用。要点は会議中ずっと画面に固定 |
| **Granola**（会議ボットを参加させずPC音声を直接取得）| 参加者に見えないボットは心理的摩擦が小さい | 会議へ参加せず、ブラウザ側でPC音声を取得（Teams連携なし） |
| **Otter.ai の集団訴訟（2025年、参加者の同意なく録音・学習に利用したと主張）** / 会議後の内輪の会話が自動共有され商談が壊れた事例 | 無断録音と自動共有は信頼を一撃で失う | 開始時に告知確認を必須化／Notion保存は**手動のみ**／自動共有なし／音声は端末内保存／無音が続くと警告 |
| 端末が落ちる・通信が切れる録音アプリ全般の失敗 | 「録れていなかった」が最悪の体験 | 入力レベルメーター・無音警告・Wake Lock・自動再接続（音声を溜めて再送）・5秒ごと音声保存 |
| 話者分離の誤判別（どのサービスにも共通）| 自動判別は必ず間違える | 発言単位の付け替え、統合、終了後の高精度再解析を用意 |
| Digg v4 / Snapchat 2017 の教訓（デザイン）| コア導線を壊す刷新は失敗する | 中心は「録音開始1タップ」「要点が常に見える」に絞り、機能を足さない |

デザインは既存アプリ（家計簿など）と同じ紺基調に、「録音」を示す朱赤だけを行動色に使用。話者は**色＋イニシャル＋名前**で示し（色だけに依存しない）、ライト/ダーク両対応、タップ領域 44px 以上、日本語の行間 1.6〜1.85 で作っています。

## 構成
```
minutes/
├─ server.js          依存ゼロのNodeサーバー（API中継＋静的配信＋合言葉認証）
├─ public/            フロント（ビルド不要・ES Modules）
│  ├─ js/audio.js     マイク＋PC音声のミックス、16kHz PCM化、録音保存
│  ├─ js/stt.js       Deepgram ストリーミング（話者分離・自動再接続）
│  ├─ js/app.js       画面（ホーム／ライブ／詳細）
│  ├─ js/store.js     IndexedDB
│  └─ js/demo.js      デモ台本
└─ test/smoke.mjs     サーバーの結合テスト（外部APIは偽サーバー）  → npm test
```

## 既知の制限
- 話者分離はライブ中は暫定精度です。重要な会議は「高精度で再解析」を推奨します。
- ブラウザの制約で、iPhone / Android はPC音声を取れません（マイク収録のみ）。
- 会議が数時間に及ぶ場合、議事録生成は分割して要約してから統合します（精度は多少下がります）。
- キー付きの実サービス（Deepgram / Claude / Notion）との通信は、キー無しの開発環境では偽サーバーでの検証までです。初回はご自身のキーで短い会議を試してください。
