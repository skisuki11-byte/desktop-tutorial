## 2. 見つけて直したバグ

- 「済」にしたあとの案内シートが、ブラウザの「戻る」で画面に残ったままになる → 画面が変わったら閉じるようにした
- 改ざんされたバックアップを読み込むと、金額が「NaN」になりうる → 読み込み時に形を検査して捨てるようにした
- ダークモードで、紫カードの上の黄色い数字のコントラストが不足 → ダーク時はカードを濃い紫に

## 3. 文字

- 本文 16px → 17px。注記・ラベルなど小さい文字も 14px 以上に（下部タブのみ 13.5px）

- 「総合窓口」表記に統一（旧「相談先をえらぶ」「宅建士への相談」の表記は残っていない）

## 4. 法的観点（公開前に専門家の確認を推奨）

| 論点 | 現状 | 残る注意点 |
|---|---|---|
| 宅建業法（紹介料） | 運営者は紹介のみ・仲介しないと明記。紹介料は不動産の成約時のみ | 顧客紹介契約書で、紹介料の条件と「利用者の負担を増やさない」ことを明記する |
| 景品表示法（ステマ規制） | 総合窓口の画面と、送信前の確認画面に紹介料の有無を表示 | — |
| 弁護士法72条・27条（非弁提携） | 弁護士からは紹介料を受け取らない | **総合窓口を不動産会社が運営する場合**、窓口が法律相談の中身に踏み込まず「取り次ぐだけ」にすること、弁護士との間で対価のやりとりをしないことを、弁護士に確認してもらう |
| 税理士法52条（税務相談） | アプリは一般的な説明と概算のみ | **窓口の担当者（不動産会社）が「特例が使えるか」などに個別に答えない**運用にする（税理士へ取り次ぐ） |
| 個人情報保護法（第三者提供） | 送信前に同意を取得。共有先を「総合窓口と提携の専門家」と表示 | 提携先の名前が決まったら、画面とプライバシーポリシーに具体名を入れる |
| プライバシーポリシー | 窓口の受付アドレスとメールアプリ送信時の扱いを追記 | 運営者名・連絡先・制定日の `[ ]` を埋める |
| 記事の正確さ | 2026年9月時点の制度で記載 | 税理士・弁護士（または司法書士）の監修を受ける |

### 残るリスク

- **受付アドレス（halufuway@gmail.com）がアプリ内に公開される。** 中継（GAS）が未設定のあいだは、メールアプリで送る宛先として `js/config.js` に書いているため、誰でも見られる。迷惑メールが増える可能性がある。GAS を設定したら、`fallbackEmail` を空にするか、窓口専用のアドレスに替えるのがよい
- メールアプリで送る方式では、相談は利用者自身のメールアドレスから届く（名前を伏せても、メールの差出人名で分かる場合がある）
- 端末内の保存（亡くなった日・試算）は暗号化していない。端末のロックに頼る
- GAS の Web アプリは誰でも呼び出せる（上限で被害を抑える設計）。相談が増えたら Cloudflare Turnstile 等のボット対策を追加する
