企画・構想書 v0.1 ／ 相続不動産アプリ

つぐいえ相続した家の「これから」を、ひとりで静かに考えられるアプリ（仮称）

相続の基本知識、売却したときの手取りシミュレーション、宅建士への相談窓口の3つを、無料のスマホアプリにまとめます。アプリは端末の中だけで完結し、個人の情報を持ちません。相談が売却の成約につながったとき、提携先の不動産会社から紹介料を受け取るモデルです。

作成日 2026年9月26日対象 iOS／Android（PWA併用）ステータス 構想案（要合意事項あり）
電話はかかってこない連絡はメールだけ。電話番号は聞かない。相談先は1社だけ。
情報を持たない計算結果は端末内だけに保存。相談内容は送るだけで、アプリ側には残さない。
お金の流れを隠さない無料の理由（成約時の紹介料）をフォームの手前で明示する。

1コンセプトと収益の流れ

相続は「期限つきの手続き」の連続です。売却を急がせるのではなく、期限と手取りを先に見せ、本人が「一度プロに聞いてみよう」と思えた時点で相談窓口を用意する。価値を先に渡し、相談は後から自然に生まれる設計にします。

知る相続の期限と基本知識
→

→
相談する匿名OK・メール必須のフォーム
→
提携宅建業者メールで返信、査定・媒介契約

ユーザー負担 0円紹介料は提携先の仲介手数料の中から支払われ、ユーザーの支払額は増えない（契約で明記）

2成功事例・失敗事例から決めたこと

この企画の主要な判断は、以下の事例の分析から導いています。どの判断がどの事例に基づくかを、各カードの下段に書きました。

失敗に学ぶ

不動産一括査定サイトの「営業電話ラッシュ」

一度の入力で複数社に情報が渡り、各社から立て続けに電話が来る。SUUMOやイエウールも自社の解説記事で「電話がしつこい」問題と対処法を扱うほど定着した不満です。送客料を払った各社が回収を急ぐ構造が原因です。

相談先は1社だけ。電話番号の欄を作らず、連絡はメールのみ。「電話は来ません」を差別化の約束として前面に出す。

成功に学ぶ

別府市「おくやみコーナー」／英国「Tell Us Once」

別府市は2016年、死亡後の手続きを一か所で案内する窓口を始め、同様の窓口が全国の自治体に広がりました。英国政府のTell Us Onceも、死亡の届け出を一度で複数の役所に伝えられる仕組みです。共通点は、遺族に「自分に関係する手続きだけ」を順番に見せていることです。

ホームは「亡くなった日」から逆算した期限タイムライン。記事は一覧で並べず、今の時期に必要なものだけを出す。

成功に学ぶ

国税庁「相続税の申告要否判定コーナー」

専門用語の多い判定を、画面ごとに一問ずつ答える形式にして、一般の人でも申告が必要かを判断できるようにしています。

シミュレーションは1画面1問のステップ入力。「取得費がわからない」「築年がわからない」にも選択肢を用意し、途中で止まらせない。

失敗に学ぶ

Zillow Offers の撤退（2021年）

米Zillowは自社の価格推定アルゴリズムを信じて住宅を買い取り、転売する事業を拡大しましたが、推定の誤差で損失を出し事業から撤退しました。機械的な価格推定は、プロでも一点で当てることが難しいという教訓です。

アプリは価格を当てにいかない。売却価格はユーザー入力で、結果は幅（±10%）で表示。正確な価格は宅建士の査定へ、という役割分担を明示する。

失敗に学ぶ

接触確認アプリ COCOA の通知不具合

Android版で接触通知が届かない不具合が約4か月間気づかれませんでした。利用者の画面では正常に見えるため、誰も異常に気づけなかったことが問題を長引かせました。

相談の送信は事業の生命線。送信結果を必ず画面で確認し、失敗時はメールアプリで送る代替手段へ誘導。運営者は週1回のテスト送信で経路を監視する。

失敗に学ぶ

ステルスマーケティング規制（2023年10月施行）

景品表示法の告示により、事業者の広告であることを隠した表示は不当表示になりました。中立な情報アプリに見せて特定業者へ誘導すると、この規制の趣旨に反し、信頼も失います。

フォームの手前に「提携先1社をご紹介します。成約時に運営者は紹介料を受け取ります」と明記。知識記事の中では特定の会社を推さない。

失敗に学ぶ

App Store審査 4.2「最低限の機能」でのリジェクト

Webサイトを包んだだけのアプリや、宣伝が主目的のアプリはAppleの審査で却下されやすいことが知られています。問い合わせフォームだけのアプリでは通りません。

オフラインで動く計算機能と期限管理を核にし、アプリ単体で役に立つ状態にする。相談窓口はその先の選択肢の1つとして置く。

3想定ユーザーと「相談したくなる瞬間」

中心は、親が亡くなり実家を相続した40〜60代です。実家は遠方で空き家になっていることが多く、兄弟姉妹と共有になるケースもあります。手続きに追われながら、家をどうするかの判断を先送りにしがちです。

主なペルソナ

佐藤さん（仮名・54歳・会社員）
東京在住。昨年、静岡の実家に一人で住んでいた母が亡くなった。弟と2人で相続。実家は築45年の木造で空き家のまま。固定資産税の通知が届き、「このままでいいのか」と気になり始めた。

  • 知りたい：売ったらいくら残るか、税金はかかるか、いつまでに何をすべきか
  • 不安：不動産会社に連絡すると営業されそう、親の家を売ることへの後ろめたさ
  • 求めるもの：自分のペースで調べられること、しつこくされないこと

相談が生まれるきっかけ

  • 期限が近づいたとき　空き家特例や取得費加算の売却期限、相続登記の義務化期限が見えると「今のうちに」と動く
  • 手取りの差が見えたとき　特例の有無で数百万円変わる試算を見ると、要件を確認したくなる
  • 持ち続けるコストが見えたとき　固定資産税・管理費が10年で積み上がる額を見ると、先送りの損に気づく

4機能構成

下部タブは4つ。「ホーム・まなぶ・はかる・そうだん」。相談は常に1タップで開けるが、アプリの主役は計算と期限管理にします（審査4.2対策と、押し売り感をなくすため）。

ホーム（期限と次の一歩）

亡くなった日を入れると、残り日数つきのタイムラインが出る。

  • 次の期限までの残り日数を最上部に大きく表示
  • 各手続きに「済」チェック（端末内保存）
  • 今の時期に読むべき記事を2本だけ提示

まなぶ（相続の基本知識）

初版は20本前後。1本3分で読める長さ、図を1枚つける。

  • 相続の流れ／法定相続分／遺産分割協議
  • 相続登記の義務化／空き家特例／取得費加算
  • 売る・貸す・持つ・手放す（相続土地国庫帰属制度）の比較
  • 記事はアプリに同梱（オフラインで読める）

はかる（売却シミュレーション）

1画面1問で入力し、手取りを幅で表示。結果は端末内に複数保存できる。

  • 売却した場合の手取り（仲介手数料・諸費用・譲渡所得税）
  • 空き家特例の要件チェックと、適用あり／なしの比較
  • 持ち続けた場合の10年間の費用
  • 相続人の人数で割った1人あたりの目安

そうだん（宅建士への相談）

匿名OK・メール必須。送信したらアプリには残さない。

  • お名前は本名でもニックネームでも可
  • シミュレーション結果を添付するかは本人が選ぶ
  • 送信先の会社名・宅建業免許番号・紹介料の有無を明示
  • 送信成功を画面で確認。失敗時はメールアプリで送る代替手段

5主要画面のラフ

藍を唯一のアクセントにして、期限と注意だけを朱で示します。遺族が使うアプリなので、明るすぎる色、祝祭的な演出、急かす言葉は使いません。文字は本文16px相当以上、タップ領域は44px以上を基準にします。

6売却シミュレーションの計算仕様

計算はすべて端末内で行います。国の制度に沿った一般的な概算で、個別の税額を確定するものではない旨を結果画面に必ず表示します。

項目計算方法例（2,000万円で売却）
売却価格ユーザー入力。わからない場合は近隣の成約事例を調べる方法を案内。結果は±10%の幅でも表示2,000万円
仲介手数料（上限）400万円超：（価格×3%＋6万円）×1.1。800万円以下の空き家等は特例で上限33万円（2024年7月改正）72.6万円
その他の費用印紙税・測量・残置物処分・解体など。既定値を置き、ユーザーが上書き30万円
取得費親が買ったときの価格。不明なら売却価格の5%（概算取得費）。相続税を払った場合は取得費加算の特例を案内100万円
譲渡所得売却価格 −（取得費＋譲渡費用）− 特別控除1,797.4万円
特別控除空き家特例の要件チェック（昭和56年5月31日以前の建築、相続直前に亡くなった人が一人暮らし、売却価格1億円以下、期限内 等）を満たせば最大3,000万円。相続人3人以上は1人2,000万円最大3,000万円
税率所有期間は亡くなった人の取得日を引き継ぐ。売った年の1月1日時点で5年超なら20.315%、5年以下なら39.63%20.315%
手取り売却価格 − 仲介手数料 − その他費用 − 譲渡所得税特例あり 1,897万円
特例なし 1,532万円
持ち続けた場合固定資産税・都市計画税、火災保険、管理（草刈り・通風）、帰省交通費を年額で入力し10年分を表示。管理不全空家に勧告されると住宅用地特例が外れ、土地の税が上がる可能性も記事で説明年額×10年

結果の保存先は端末内だけ

Capacitor Preferences（Web版は localStorage）に保存。複数件を名前つきで保存・比較・削除できる。機種変更に備え、JSONで書き出す機能を用意（既存アプリ「ともしび」と同じ方式）。

計算で扱わないもの

相続税額の個別計算、遺産分割の配分の提案、特例の適否の断定。これらは税理士・弁護士の業務範囲にかかるため、アプリは「要件の一般的な説明」と「専門家への確認を促す」に留める。

7相談フォームの項目

入力項目は少ないほど送信率が上がります。宅建士が最初の返信を書くのに必要な最小限だけを聞き、電話番号と住所の番地は聞きません。

項目必須内容・理由
お名前任意本名でもニックネームでも可。空欄なら「匿名」として送る
メールアドレス必須返信先。形式チェックと、確認用の再入力なしで打ち間違いを防ぐため送信前の確認画面で大きく表示
物件の場所任意都道府県・市区町村まで。提携先の対応エリア外なら、送信前にその旨を表示
物件の種類任意戸建て／土地／マンション／その他
相談の内容必須よくある相談をチップで選べる（売るか迷っている、価格を知りたい、特例を使えるか、共有者と話がまとまらない、遠方で管理できない）＋自由記述（1,000字まで）
試算結果の添付任意保存済みの試算から1件選んで本文に添える。既定はオフ
送信への同意必須送信先の会社名・免許番号・紹介料の有無・運営者が内容を保存しないことを示した上での同意（個人情報保護法の第三者提供）

「匿名」は本名を出さなくてよいという意味です。返信にメールアドレスが必要なため、完全な匿名ではないことをフォーム内で正直に書きます。気になる人向けに「相談用のメールアドレスを別に作る方法」の記事を用意します。

GAS側の処理イメージ

// 受け取ったらメールを送るだけ。どこにも書き込まない。
function doPost(e) {
  const d = JSON.parse(e.postData.contents);
  if (d.website) return ok_();            // ボット用の見えない欄
  if (!/^[^@\s]+@[^@\s]+$/.test(d.email)) return ng_('email');
  if (overLimit_()) return ng_('busy');   // 1時間あたりの上限
  const to = PropertiesService.getScriptProperties()
               .getProperty('TO');        // 宛先はアプリに含めない
  MailApp.sendEmail({
    to, replyTo: d.email,
    subject: '【つぐいえ相談】' + (d.area || 'エリア未記入'),
    body: format_(d)                      // 本文を組み立てる
  });
  return ok_();
}

実装上の注意

  • ユーザーのメールアドレスに自動返信しない。誰でも任意のアドレスへメールを送れる踏み台になるため。控えは送信前の確認画面で見せる
  • アプリからは Content-Type: text/plain でPOSTし、ブラウザの事前確認（CORS preflight）を避ける
  • ボット対策は、見えない入力欄・1時間あたりの送信上限・文字数上限の3つ。相談が増えたらCloudflare Turnstileを追加
  • GASのURLはアプリに含まれるため秘密ではない前提で設計する（悪用されても宛先1つにしか届かず、上限で止まる）
  • 運営者は週1回テスト送信し、届かなければすぐ気づけるようにする

アプリ本体

このリポジトリの「ともしび」と同じく、依存ライブラリなしの HTML/CSS/JS を Capacitor で iOS／Android アプリにします。ビルドと TestFlight 配信は既存の Codemagic 設定にワークフローを1つ足すだけで済みます。同じコードをPWAとしてWebでも公開でき、検索からの流入口にもなります。アプリ内に解析ツール（行動トラッキング）は入れません。

9法務・コンプライアンスの整理

紹介料モデルと相続の情報提供は、複数の法律の境界にあります。リリース前に、提携先の宅建業者と、できれば弁護士に下記を確認してもらう前提です。

宅地建物取引業法紹介料の受け取り
運営者は宅建業の免許がないため、「紹介」に徹する。物件の説明、価格や条件の交渉、契約の調整には一切関与しない。この条件なら反復継続した顧客紹介でも宅建業に当たらないとの政府見解がある（経済産業省・国土交通省、グレーゾーン解消制度）。提携先と顧客紹介契約書を結び、紹介料の条件と、ユーザーの負担を増やさないことを明記する。
税理士法税の相談
税理士でない者は、無償でも個別の税務相談を業として行えない。アプリは一般的な制度説明と概算ツールに留め、「あなたの場合は○○円」と断定する表現や、個別の質問への回答はしない。
弁護士法72条法律相談
遺産分割の交渉や、共有者間の争いへの助言は弁護士の業務。記事は一般論に留め、争いがある場合は弁護士・法テラスを案内する。宅建士への相談も「不動産の売却」に関する範囲とする。
個人情報保護法第三者提供
相談内容を提携先に渡すことは第三者提供にあたるため、送信前に送信先を明示した上で同意を取る。プライバシーポリシーで、運営者が保存しないこと、提携先の受信箱には残ること、提携先の利用目的を説明する。
景品表示法ステマ規制
運営者が紹介料を受け取ることを、フォームの手前とアプリ説明文に明記する。記事の中で提携先を宣伝しない。
App Store／Google Playプライバシー表示
送信した内容が提携先の受信箱に残る以上、Appleの定義では「収集」に当たる。「連絡先情報（名前・メール）」「ユーザーコンテンツ」を、アプリ機能の目的・トラッキングなしとして申告する。プライバシーポリシーのURLを用意する（ともしびと同じ構成）。

計測の方針

アプリ内に行動トラッキングを入れない代わりに、ストアの統計（ダウンロード数）と、提携先が受け取った相談メールの件数・その後の結果を月1回共有してもらう形で計測します。紹介料の精算にも同じ記録を使うため、相談メールの件名に通し番号を入れます。
