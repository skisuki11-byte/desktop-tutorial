# ともしび

亡くなったペットのおうち。毎日ひらいて、おまいりして、庭に花を増やしていきます。

`index.html` をブラウザで開くだけ。インストール・ビルド・通信は一切不要で、
スマホでもオフラインで動きます。写真・動画・記録は端末の中だけに残ります。

- デザイン案（Claude Design のキャンバス）：[`design/`](design/)
- 設計の判断と根拠：[`docs/UI設計.md`](docs/UI設計.md)
- 最初のUI案（夜の弔い版）：[`proposal.html`](proposal.html)

## 画面

```
おむかえ（なまえ → いぬ/ねこ → 写真 → 日づけ）
   ↓
おうち ─→ おまいり（4動作＋季節のおそなえ）─→ おまいりのあと（通算◯回目・庭に花が1つ）
   │
   ├─ おまいりの庭   花＝おまいりの通算。あの日までの節目も
   ├─ アルバム       端末の写真を期間で章立て。出さない期間を指定できる
   ├─ うごく        端末の動画。いつでも、なんども
   └─ 設定
```

## つくりの要点

- **数えるのは通算だけ。** 連続記録（ストリーク）は入れない。1日休むと途切れ、
  弔いに罪悪感を接続するため。通算と庭の花は**減らない・枯れない・途切れない**。
- **写真が入ればイラストは消える。** いぬ・ねこの絵は、写真が入るまでの代役。
- **おまいりは順序固定の4動作**（灯明→水→ごはん→花）。完了時におりんを1打
  （WebAudioで合成、毎回同じ音）。季節のおそなえだけ月がわりで1つ増やせる。
- **動画はいつでも見られる。** 年に一度という制約は置かない。
  これは Continuing Bonds（継続する絆／Klass, Silverman & Nickman, 1996）の考え方に沿う。
- **ほかの人の数は出さない。** ランキングも比較もない。

## 保存のしくみ

保存先が3つある。環境によって使えるものが違うので、起動時にしらべて順に試す。
どこに何があるかは索引（`tomoshibi.index.v1`）に持つ。

| 保存先 | 使える場面 | 入るもの |
|---|---|---|
| IndexedDB | ホーム画面に追加した／ブラウザで直接開いた | 写真・動画とも、形式も大きさも自由 |
| artifact の `assets` | claude.ai のページとして開いた | 写真と、mp4・webm の動画1本20MBまで |
| localStorage | 上の2つが両方だめなとき | 写真1枚ぶん |

**動画は「このブラウザで再生できるか」を先に確かめてから保存する。**
開けないものを入れても、あとで真っ黒な動画が残るだけなので。
iPhone の `.mov` は中身が mp4 と同じ ISO-BMFF のことが多いため、
再生できると確かめたものは mp4 と申告して通す。

### 一度こわれた経緯（記録）

最初の版は、**IndexedDB が使えない環境で写真が入らないまま無言で止まっていた**。

| 原因 | 直しかた |
|---|---|
| 埋め込み表示や iOS Safari の制限で IndexedDB が使えない | 起動時に「実際に書いて消す」試験をして可否を判定し、使える保存先へ回す |
| 失敗を誰も受け取っていなかった（`.catch` が無かった） | すべての保存は必ず解決し、`{ok:false, reason}` を返す。理由はその場で画面に出す |

HEIC など端末で開けない形式も、黙って落とさず理由を出す。
設定の「保存のようす」で、いまどこに保存しているかが見られる。

## 確認のしかた

設定の「日づけを仮に進めて確かめる」で、四十九日・一周忌の画面を待たずに見られます。
通常は「今日」のまま。

## 実装しないと決めたUI

連続お参り記録（ストリーク）／達成バッジ・紙吹雪／ランダムに届く思い出／
退会引き止め／他人との比較／常時対話できるAIチャット。

いずれも継続率を確実に上げる実証済みの手法です。採らない理由は
[`docs/UI設計.md`](docs/UI設計.md) に事例つきで書いてあります。
**足したくなったら先にそれを読んでください。**

## 注意

「つらいときの相談先」は、実在と受付状況を確認できた窓口だけを載せます。
確認できていないものは載せません。
