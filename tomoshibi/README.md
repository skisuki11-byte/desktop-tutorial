# ともしび

亡くなったペットのおうち。毎日ひらいて、おまいりして、庭に花を増やしていきます。

`index.html` をブラウザで開くだけ。インストール・ビルド・通信は一切不要で、
スマホでもオフラインで動きます。写真・動画・記録は端末の中だけに残ります。

- デザイン案（Claude Design のキャンバス）：[`design/`](design/)
- 設計の判断と根拠：[`docs/UI設計.md`](docs/UI設計.md)
- 最初のUI案（夜の弔い版）：[`proposal.html`](proposal.html)

## 画面

```
おむかえ（なまえ → いぬ/ねこ → 写真 → 日づけ）
   ↓
おうち ─→ おまいり（4動作＋季節のおそなえ）─→ おまいりのあと（通算◯回目・庭に花が1つ）
   │
   ├─ おまいりの庭   花＝おまいりの通算。あの日までの節目も
   ├─ アルバム       端末の写真を期間で章立て。章を開いて一枚ずつ見られる
   ├─ うごく        端末の動画。いつでも、なんども
   └─ 設定
```

## つくりの要点

- **数えるのは通算だけ。** 連続記録（ストリーク）は入れない。1日休むと途切れ、
  弔いに罪悪感を接続するため。通算と庭の花は**減らない・枯れない・途切れない**。
- **写真が入ればイラストは消える。** いぬ・ねこ・そのほか（足あと）の絵は、写真が入るまでの代役。
- **おまいりは順序固定の4動作**（灯明→水→ごはん→花）。4つそろった時点で通算に数え、
  おりんを1打（WebAudioで合成、毎回同じ音）。**ただし画面はそこで終わらせない。**
  季節のおそなえと「好きだったもの」をそなえる余地を残し、「おまいりを終える」で締める。
- **好きだったものをそなえられる。** さつまいも、ボール、まくらの角。3つまで。
- **この子への手紙を書ける。** 書いて「とどける」。何を書くべきかは指定せず、
  書き出しの候補だけ出す。
- **いまの気分。** おまいりのあとに、「重い」〜「前を向けた」の5段階で残せる（任意）。
  庭の画面で波として見える。**点数でも達成度でもない。**
  死別への対処は行ったり来たりしながら進む（Dual Process Model／Stroebe &amp; Schut, 1999）ため、
  平均も目標線も出さない。重い日が5日続いたときだけ、相談先をそっと出す。
- **戒名がある。** 旅立った季節・名の一字・生まれた季節から、この子だけの6字を選ぶ。
  **お寺が授けたものではない**ことを画面に明記し、どの字がどこから来たかを全部見せ、
  書きかえも、出さないことも選べる（理由は `docs/UI設計.md` の追記4）。
  トップには享年と命日も出る。
- **動画はいつでも見られる。** 年に一度という制約は置かない。
  これは Continuing Bonds（継続する絆／Klass, Silverman & Nickman, 1996）の考え方に沿う。
- **ほかの人の数は出さない。** ランキングも比較もない。
- **好きだったものをそなえられる。** さつまいも、ボール、まくらの角。3つまで登録できる。
- **飼い主からこの子へ手紙を書ける。** 書いて「とどける」。書いた手紙は端末の中に残る。
  何を書くべきかは指定せず、書き出しの候補だけ出す。
- **アルバムは何も隠さない。** 章を押せば写真が並び、押せば一枚ずつ大きく見られる。
  隠す機能は置かない。自分で入れた写真なので、要らなくなれば消せばよい
  （理由は `docs/UI設計.md` の追記2・追記3）。

## 保存のしくみ

**保存先はこの端末の中だけ。どこにも送らない。**
外に預けないので流出しようがなく、こちらのストレージ費用もかからない。
そのかわり端末を変えるときは、バックアップを書き出して新しい端末で読み込ませる。

| 保存先 | 使う場面 | 入るもの |
|---|---|---|
| IndexedDB | 本命 | 写真・動画とも、形式も大きさも制限なし |
| localStorage | IndexedDB が使えないときの保険 | 写真1枚ぶん |

動画は「このブラウザで再生できるか」を先に確かめてから保存する。
開けないものを入れても、あとで真っ黒な動画が残るだけなので。

**IndexedDB には Blob をそのまま入れない。** iOS Safari は Blob を一時ファイルへの
参照として持つため、アプリを閉じると実体だけが消え、記録は残るのに中身が空になる。
実際にそれが起きた（遺影が壊れた画像アイコンになり、動画のタイトルだけが残った）。
中身は ArrayBuffer で持ち、読むときに Blob へ組み直している。

読み出しで中身が失われていたものは数えて、おうちの画面で知らせる。
壊れた画像を黙って見せない。「読めない記録を消す」で片付けられる。

### 消える環境がある

**別のページに埋め込まれた状態（iframe）で開くと、閉じたときに保存が消えることがある。**
Safari はその状態の保存を一時的なものとして扱うため。
アプリはこれを検出して、おむかえ・おうち・設定の3か所で先に知らせる。
「ホーム画面に追加」して開けば、消えない保存になる。

起動時に `navigator.storage.persist()` でブラウザに「勝手に消さないでほしい」と頼む。
設定の「保存のようす」で、いまどこに保存していて、それが保護されているかが見られる。

### バックアップ（機種変）

設定 →「バックアップを書き出す」で、写真・動画・記録を1つのJSONにまとめる。
新しい端末では「バックアップから戻す」でそのファイルを読み込ませる。
戻すときは、いま入っているものを全部消してから入れ直す（混ざると分かりにくいため）。

### 一度こわれた経緯（記録）

最初の版は、**IndexedDB が使えない環境で写真が入らないまま無言で止まっていた**。

| 原因 | 直しかた |
|---|---|
| 埋め込み表示や iOS Safari の制限で IndexedDB が使えない | 起動時に「実際に書いて消す」試験をして可否を判定する |
| 失敗を誰も受け取っていなかった（`.catch` が無かった） | すべての保存は必ず解決し、`{ok:false, reason}` を返す。理由はその場で画面に出す |

HEIC など端末で開けない形式も、黙って落とさず理由を出す。

## 確認のしかた

設定の「日づけを仮に進めて確かめる」で、四十九日・一周忌の画面を待たずに見られます。
通常は「今日」のまま。

## 実装しないと決めたUI

連続お参り記録（ストリーク）／達成バッジ・紙吹雪／ランダムに届く思い出／
退会引き止め／他人との比較／常時対話できるAIチャット。

いずれも継続率を確実に上げる実証済みの手法です。採らない理由は
[`docs/UI設計.md`](docs/UI設計.md) に事例つきで書いてあります。
**足したくなったら先にそれを読んでください。**

## 注意

「つらいときの相談先」は、実在と受付状況を確認できた窓口だけを載せます。
確認できていないものは載せません。
