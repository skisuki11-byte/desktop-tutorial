# 春高タオル — 出場記念タオルの申し込みと集計

春高バレー出場記念タオルを、各家庭がスマホから申し込み、役員が合計枚数と「誰が何枚か」を確認するための Web ページです。

| 画面 | 使う人 | URL | できること |
|---|---|---|---|
| 申し込み（`index.html`） | 各家庭 | `…/towel/` | お名前・コードネーム・枚数を入力 → 確認 → 申し込む。あとから修正・取り消し |
| 集計（`admin.html`） | 役員（数名） | `…/towel/admin.html` | 合言葉で入る。合計枚数、誰が何枚、集金・受け渡しのチェック、CSV／コピー |

申し込み画面には役員ページへのリンクを置いていません。集計の URL は役員だけで共有してください。
データは役員の Google スプレッドシートに貯まります。設定手順は [`gas/README.md`](gas/README.md) にあります。

## 申し込みの流れ（各家庭）

1. **入力**：お名前（必須）、コードネーム（任意）、枚数（−／＋ か 1・2・3・5枚のボタン）を入れて［確認する］を押す
2. **確認**：お名前と枚数を大きく表示する。［修正する］で入力に戻るか、［申し込む］で送信する
3. **完了**：お名前・枚数・受付番号を大きく表示する。［修正する］か［閉じる］を押す

同じ端末でもう一度開くと「この端末からの申し込み」が出て、そこから修正・取り消しができます。

## 集計画面（役員）

- いちばん上に **合計枚数**（業者への発注数）を大きく表示。集金・受け渡しの進み具合も並べる
- 一覧で **誰が何枚か** を確認。名前・コードネーム・受付番号でさがす、未集金・未渡しでしぼる、並べかえる
- 集金・受け渡しのチェックには **つけた役員の名前と時刻** が残る（二重の集金を防ぐ）
- 1分ごとに自動で最新にする（ほかの役員がつけたチェックも反映）
- LINE や口頭で受けた分は［代わりに追加］で入れる。取り消しは［元に戻す］で取り返せる
- ［集計をコピー（LINE用）］で「合計 ◯枚（◯件）」の報告文をコピー。［CSVで保存］［表をコピー］で業者や会計に渡せる

## 設計の根拠（ほかの事例の成功・失敗から）

| 判断 | 根拠にした事例 |
|---|---|
| 家庭はログインなしで申し込める | Doodle の日程調整はアカウント登録なしで参加でき、参加の手間が少ないことで広まった。保護者全員に何かのアカウントを作らせると、そこで止まる家庭が出る |
| 入力欄は3つだけ。コードネームは任意 | Expedia は予約フォームの任意項目「会社名」を1つ削っただけで年 1,200 万ドルの増益になったと報告している。欄は増やすほど離脱が増える |
| 入力 → 確認 → 完了。確認と完了で名前と枚数をいちばん大きく | GOV.UK Design System の「Check answers（回答の確認）」パターン。送る前に見直せる画面があると、まちがいに自分で気づける。完了画面で同じ表示を繰り返すと「ちゃんと届いた」と確信できる |
| 値段と合計金額を最初から見せる | Baymard Institute の調査では、送料・手数料などの追加費用が予想より高かったことが、ネット通販の決済での離脱理由の1位。集金額は申し込む前にわかるようにする |
| ラベルは欄の上に置き、例は別の行に書く | Nielsen Norman Group の調査で、入力欄の中の薄い文字（placeholder）をラベル代わりにすると、入力を始めた瞬間に何の欄かわからなくなり、まちがいが増えることが示されている |
| まちがいは「欄の横」と「まとめ」の両方に、直し方まで書く | GOV.UK の error summary パターン。どこを、どう直せばよいかを一度に示す |
| 送信後も修正・取り消しができる | Google フォームは初期設定では送信後に回答を直せない（「回答の編集を許可」を有効にする必要がある）。直せないと「もう一度送る」家庭が出て、二重集計の原因になる |
| 通信が切れて押し直しても1件だけ | Stripe の決済 API の「冪等キー」と同じ考え方。申し込みごとに番号をつけ、同じ番号の再送は1件にまとめる |
| 役員の取り消しは確認ダイアログではなく［元に戻す］ | Gmail の「送信取り消し」。毎回の「よろしいですか？」は読まれずに押されるようになるので、あとから取り返せるほうが安全 |
| 家庭側の取り消しは赤い文字ボタン → その場で赤い確認 | 2018 年のハワイのミサイル誤警報は、訓練と本番の操作が見分けにくい画面で起きた。取り返しのつかない操作は、ほかのボタンと見た目をはっきり変える |
| 1列のレイアウト、ボタンは大きく（高さ 48〜64px） | 2000 年の米大統領選、パームビーチの「バタフライ投票用紙」は、名前と穴の対応がわかりにくい配置で誤投票を招いた。スマホでは1列にして、ラベルと入力欄を必ず隣り合わせる |
| 本文は BIZ UDPゴシック 17px | モリサワの UD（ユニバーサルデザイン）書体。保護者・祖父母世代が小さなスマホで読んでも字形を取りちがえにくい |
| 状態は色だけでなく ✓ と文字でも示す | 色覚の多様性への配慮（WCAG 1.4.1）。「集金済み／未集金」を文字でも書く |

## 見た目

- 紺（部活のジャージ）とボールの黄色の2色。黄色は「押すボタン」と「いま選んでいる枚数」にだけ使う
- 見出しはタオルのプリントのような太い書体（Dela Gothic One）、数字は得点板のような Barlow Condensed
- 申し込み画面の上に、選んだ枚数ぶん重なるタオルの絵を出す
- ダークモード対応

## ファイル

```
index.html          申し込み画面（各家庭）
admin.html          集計画面（役員）
css/style.css       見た目（両画面共通・ダークモード対応）
js/config.js        公開前に書きかえる設定（集計先 URL・チーム名・値段・締切 など）
js/api.js           集計先とのやりとり、入力チェック、デモ表示
js/form.js          申し込み画面の動き
js/admin.js         集計画面の動き
gas/Code.gs         集計先（Google Apps Script）。スプレッドシートに貯める
gas/appsscript.json GAS の設定（権限は「このスプレッドシートの読み書き」だけ）
gas/README.md       集計先の設定手順
tests/gas.test.js   集計先のテスト（node towel/tests/gas.test.js）
```

## デモ表示で試す

`js/config.js` の `endpoint` が空のあいだはデモ表示です。入力はその端末の中にだけ保存され、集計画面には見本の申し込みが並びます（合言葉は `demo`）。
